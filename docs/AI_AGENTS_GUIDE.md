# AI Agent 使用指南

本文档规定 Scenecaps 项目中 AI Agent 的使用规范，作为[生成式 AI 使用方针](AI_USAGE_POLICY.md)的补充。当本文与使用方针存在冲突时，以使用方针为准。

本文所称 AI Agent，指具备自主规划、工具调用或代码修改能力，并能连续执行多步操作的自动化系统。仅用于补全、检索或翻译的工具，按照使用方针处理。

---

## 一、基本立场

AI Agent 可以显著提高本地开发效率，但不会改变贡献者的根本责任。使用 Agent 完成的任何工作，其正确性、安全性与合规性仍由贡献者承担。

Agent 的行为边界由其使用者负责设定。使用者不得以「Agent 自行决定」为由，规避应有的审查与确认。

---

## 二、核心原则

| 原则 | 说明 |
| --- | --- |
| 人工监督 | Agent 的操作应在人工监督下进行 |
| 最小权限 | Agent 仅获得完成任务所需的权限 |
| 可审计 | Agent 的关键操作应可追溯 |
| 可中断 | 人类可在任意时刻中断 Agent |
| 人工确认 | 面向外部的操作须经人工确认 |

---

## 三、允许的辅助操作

在人工监督下，Agent 可以执行以下本地任务：

- 阅读和分析源码；
- 搜索调用关系与相关实现；
- 提出修改方案供人工确认；
- 生成或修改本地代码，供人工审查后提交；
- 执行本地构建、测试与静态检查；
- 整理供贡献者自行审查的技术信息。

使用 Agent 完成上述工作，不免除贡献者的理解、验证与披露义务。提交者必须检查 Agent 对文件所做的实际修改，不得仅依据 Agent 的完成报告判断任务已正确执行。

---

## 四、禁止自主执行的操作

未经人类明确操作与确认，Agent 不得自主执行以下行为：

- 创建或提交面向项目的 Pull Request；
- 创建 Issue 或发布讨论；
- 发布 PR 审查评论及其他公开回复；
- 批准、合并或关闭 Pull Request；
- 代表维护者作出项目管理决定；
- 执行超出授权范围的仓库管理操作。

不得通过反复自动确认 Agent 的请求，变相绕过上述人工要求。

---

## 五、提交身份与签名

- 项目要求提交具备有效签名；
- 提交者不得将个人签名私钥交由 Agent 持有、管理或用于自主签署；
- 不得将访问令牌、仓库凭据或其他敏感信息直接提供给未经适当限制的 Agent；
- 所有需要确认贡献者身份的提交与发布行为，必须由具备相应权限的人类参与并承担责任。

---

## 六、日志与审计

使用 Agent 时，应保留可核查的操作记录，包括但不限于：

- Agent 执行的命令序列；
- 读取或修改的文件列表；
- 执行的构建与测试命令及其结果；
- 错误信息与处理过程；
- 人工介入或确认的时间点。

日志可在 Pull Request 描述中摘要说明，完整日志可按需提供。日志不应用于记录密码、令牌或其他敏感信息，必要时应在保留前加以脱敏。

---

## 七、维护者使用 Agent

维护者可以使用 Agent 辅助源码分析、技术研究与问题排查，但应遵守以下限制：

- AI 不得代替维护者作出合并、关闭、处罚等管理决定；
- 不得将未经核实的模型结论直接作为要求他人修改的依据；
- 公开发布的审查意见与项目管理回复应由维护者本人撰写，AI 仅可用于翻译或语法校正；
- 不得以 AI 检测器的结果作为认定违规的唯一依据。

---

## 八、自动化例外

项目已有的确定性自动化流程不受本文关于自主 Agent 的限制，包括预先配置的构建、测试与其他常规任务。

由维护者明确批准、具有固定执行范围与责任人的自动化操作，可根据实际情况单独处理。此类例外不代表允许自动化流程不受限制地创建贡献、发布评论或修改项目内容。

---

## 九、责任

使用 Agent 的贡献者对其被修改的所有内容负责。因 Agent 操作导致的缺陷、泄露或其他问题，由使用者承担相应责任。

---

## 十、修订

本指南可根据 AI 工具的发展与项目实践进行修订。涉及贡献者义务、禁止行为或凭证处理的实质性修改，应通过正式文档更新发布，并与[生成式 AI 使用方针](AI_USAGE_POLICY.md)保持同步。
