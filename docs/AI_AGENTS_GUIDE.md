# AI Agent 使用指南

本文档定义 Scenecaps 项目中 AI Agent 的使用规范，作为 `AI_USAGE_POLICY.md` 的补充规范。

---

## 1. Agent 行为准则

### 核心原则

- **人工监督优先** - Agent 所有操作必须在人工监督下进行
- **最小权限** - Agent 仅拥有完成任务所需的最小权限
- **可审计性** - 所有 Agent 操作必须可追溯、可审查
- **可中断** - 任何时刻人类可中断 Agent 执行

### 行为边界

| 允许 | 禁止 |
| ------ | ------ |
| 读取、分析源码 | 自主创建/提交 PR |
| 搜索调用关系、查找实现 | 自主创建 Issue/评论 |
| 提出修改方案供人工确认 | 自主合并/关闭 PR |
| 生成/修改本地代码供人工确认 | 代表维护者做决策 |
| 执行本地构建/测试/静态检查 | 使用个人凭据/私钥 |
| 整理技术信息供贡献者自行审查 | 绕过人工确认直接执行 |

---

## 2. 允许的辅助操作

在人工监督下，Agent 可协助以下本地开发任务：

- 阅读和分析源码结构
- 搜索调用关系、查找相关实现
- 提出修改方案供人工确认
- 生成或修改本地代码（需人工确认后提交）
- 执行本地构建、测试及静态检查
- 整理技术信息供贡献者自行审查

**关键要求**：使用 Agent 完成上述工作，不免除贡献者的理解、验证及披露义务。提交者必须检查 Agent 对文件进行的实际修改，不得仅根据 Agent 的完成报告判断任务已正确执行。

---

## 3. 禁止自主执行的操作

未经明确的人类操作和确认，不得允许 AI Agent 自主执行：

- 创建或提交面向项目的 PR
- 创建 Issue 或发布讨论
- 发布 PR 审查评论及其他公开回复
- 批准、合并或关闭 PR
- 代表维护者作出项目管理决定
- 执行超出授权范围的仓库管理操作

不得通过简单地自动确认 Agent 的操作请求，规避上述人工参与要求。

---

## 4. 提交身份与签名

- 项目要求 Git 提交具有有效 GPG 签名
- 提交者不得将个人签名私钥交由 AI Agent 持有、管理或用于自主签署提交
- 不得将个人访问令牌、仓库管理凭据或其他敏感凭据直接提供给未经适当限制的 Agent
- 所有需要贡献者身份确认的提交和发布行为，必须由具备相应权限的人类参与并承担责任

---

## 4. 日志与审计

使用 Agent 时必须保留完整日志，包括但不限于：

- Agent 执行的命令序列
- 读取/修改的文件列表
- 执行的构建/测试命令及结果
- 错误信息及处理过程
- 人工介入/确认的时间点

日志应在 PR 描述中摘要说明，完整日志可按需提供。

---

## 5. 维护者使用 AI Agent

维护者可使用 AI Agent 辅助：

- 源码分析、技术研究
- 问题排查、根因定位
- 内部审查辅助（总结变更、查找潜在问题）

**禁止**：

- AI 代替维护者作出合并/关闭/处罚等项目管理决定
- 直接将未经确认的模型结论作为要求贡献者修改的依据
- 公开发布的审查意见由 AI 直接生成（仅可用于翻译/语法校正，需披露）
- 使用 AI 检测器或模型推测结果作为认定违规的唯一依据

---

## 5. 自动化例外

以下确定性自动化流程不受上述 Agent 限制：

- 预先配置的 CI/CD 构建、测试流程
- 由维护者明确批准、具有固定执行范围和责任人的自动化操作
- 预先配置的代码格式化、静态检查等常规 CI 任务

此类例外不代表允许自主 Agent 不受限制地创建贡献、发布评论或修改项目内容。使用 AI 的自动化流程仍须符合相关的安全、信息保护和质量要求。
